## Decrypt firmware image

Latasin aluksi [tp-link-decrypt](https://github.com/robbins/tp-link-decrypt) -ohjelman repon `git clone`-komennolla:

```bash
git clone https://github.com/robbins/tp-link-decrypt.git
cd tp-link-decrypt
```

Työkalu tarvitsee toimiakseen TP-Linkin firmwaresta itsestään puretut RSA/DES-avaimet, joilla firmware on allekirjoitettu/salattu. Asensin ensin riippuvuudet ja ajoin avainten purkuskriptin:

```bash
./preinstall.sh
./extract_keys.sh
```

Tämän jälkeen käänsin itse dekryptaustyökalun:

```bash
make
```

Latasin TapoV3-firmwaren binaryn suoraan TP-Linkin S3-buketista:

```bash
aws s3 cp s3://download.tplinkcloud.com/firmware/Tapo_C200v3_en_1.4.2_Build_250313_Rel.40499n_up_boot-signed_1747894968535.bin Tapo_C200v4_en_1.4.2.bin --no-sign-request
```

Ja lopuksi dekryptasin ladatun firmware-imagen käännetyllä työkalulla:

```bash
bin/tp-link-decrypt Tapo_C200v4_en_1.4.2.bin Tapo_C200v4_en_1.4.2.decrypted.bin
```

*(liitä tähän kuvakaappaus komennon onnistuneesta ajosta / tulostiedoston syntymisestä)*

Tuloksena saatiin dekryptattu firmware-binääri, jota voitiin seuraavaksi analysoida ja josta voitiin purkaa varsinainen tiedostojärjestelmä.



Latasin TapoV3-firmwaren binaryn suoraan TP-Linkin S3-buketista:

## Analyse the image file

Aloin tutkia lisää dekryptattuja tiedostoja ja löysin kinnostavan tiedoston squashfs-root, jonka löysin `binwalk`-työkalulla, joka tunnisti sisällöstä squashfs-tiedostojärjestelmän ja purki sen automaattisesti erilliseen `squashfs-root`-kansioon:


<img width="156" height="96" alt="image" src="https://github.com/user-attachments/assets/56669d5e-4f24-4e67-8c2c-5ddc8ab20a4a" />

Tarkastelin purettua squashfs-root-kansiota tarkemmin ajamalla ls -la sen sisällölle. Kansiosta löytyi mm. bin/, config/, etc/, lib/ ja usr/ -hakemistot, jotka viittasivat siihen että kyseessä olisi laitteen juuritiedostojärjestelmä. 

Kuitenkin kun tarkastelin etc/-kansion sisältöä lähemmin, huomasin ettei se sisältänytkään tavanomaisia Linux-järjestelmätiedostoja (esim. passwd, shadow, init.d/), vaan pelkästään sovelluskohtaista dataa, kuten data/, sensor, dsd_convert.json ja webrtc_profile.ini. Tämä viittasi siihen, ettei kyseinen squashfs-root ollutkaan koko laitteen rootfs, vaan yksi useammasta erillisestä osiosta (partition) firmware-imagen sisällä.
